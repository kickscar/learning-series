# Rule: style-guide

문서 스타일 공통 규칙. 모든 write skill에 적용.

---

## 헤딩 규칙

### 이론/개념 섹션

| 레벨 | 용도 | 형식 |
|------|------|------|
| H1 | 개념/토픽명 | `# {개념명}` — 번호 없음 |
| H2 | 하위 주제 | `## 1. {주제명}` — 번호 있음 |
| H3 | 세부 항목 | `### ① {항목}` — ①②③ 패턴 |

### 실습 섹션

| 레벨 | 용도 | 형식 |
|------|------|------|
| H1 | 작업 단계 | `# 1. {단계명}` — 번호 있음 |
| H2 | 콘솔 스텝 / 리소스 단위 | `## 1. {콘솔} > {서비스 한글}(영문) > **{최종 화면 한글}(영문)**` — 형식은 `CLAUDE.md > 플랫폼 상수` 참조 |
| H3 | 세부 항목 | `### ① {항목}` 또는 `### 1. {항목}` |

- **헤딩에 볼드(`**`) 처리 안 함**
- H1 `# 전체 아키텍처`, `# 사전 준비`, `# 핵심 정리`, `# 참고 자료` 고정
- **콘솔 경로는 절대 코드박스(```` ``` ````)에 넣지 않는다** — H2 헤딩으로 쓴다. 코드박스 안에서는 `**볼드**`도 렌더링되지 않는다. `text` fence는 출력·로그 전용(`rules/code-blocks`)

---

## 문서 시작 규칙

- **챕터명/섹션명 헤딩 없이 시작** — Notion 타이틀이 대신
- 이론 섹션: 첫 H1 전에 개요 단락 1~3줄 (앞 섹션 환기 + 이번 섹션 예고)
- 실습 섹션: 설명 텍스트 1~2줄 + `### 실습 목표`

---

## 섹션 골격 (전체 조립)

위 헤딩·시작 규칙을 조립한 섹션 전체 골격. 개념 전개는 **정의 → 역할·사용 맥락 → 연결 관계 → 정리·비교** 순.

### 이론 섹션 (실습 없음)

```
{개요 단락 1~3줄}              앞 섹션 환기 + 이번 예고

# {개념명}                     H1 번호 없음. 개념/토픽 단위
  {정의 → 역할 → 연결 관계 → 비교표}
  ## 1. {하위 주제}            필요 시
  {mermaid 또는 [이미지:] + 해설 2~4줄}
# {다음 개념명}
...

# 핵심 정리                    필수 고정
# 참고 자료                    필수 고정 (공식 문서 링크)
```

### 이론 + 실습 (혼합) 섹션

```
{설명 1~2줄}

# {이론 파트 개념명}            실습 앞 개념 (이론 골격 압축)
...
# 핵심 정리                    이론과 실습 사이에 둔다

# [실습] lab{NN}: {제목}        H1 번호 없음
### 실습 목표
### 사전 준비
[이미지: 전체 아키텍처] + 해설   lab 오프닝(전체 리소스·연결)

# 1. {단계명}                  H1 번호 있음 (작업 단계)
  ## 1. {콘솔 경로 > **최종 화면**}
  [콘솔화면: ...]
  **{탭명}** + 설정값 표(필드·값·비고)
  **확인** + 표(항목·예상)
# 2. {단계명}
...
# N. 자원 정리                 실습 종료(리소스 정리 또는 유지+handoff)

# 참고 자료
```

- 순수 이론형은 `# 핵심 정리` 뒤 바로 `# 참고 자료`. 혼합형은 `# 핵심 정리`가 이론과 실습 사이.
- Gallery 섹션은 혼합형 골격을 따르되 실습 헤딩이 `# [실습] Gallery: {작업명}`.

## 이미지 플레이스홀더

> 콘솔 이름은 `CLAUDE.md > 플랫폼 상수` 참조.

```
[콘솔화면: {콘솔} > {서비스} > {화면} > {핵심 포인트 설명}]
[이미지: {개념/구조 설명} — {독자가 봐야 할 포인트}]
```

- 콘솔 캡처가 필요한 모든 지점에 명시
- 플레이스홀더 뒤에 해설 1~2줄 추가 (선택)

## 설정값 / 확인값 표기

- **고정값**(항상 이 값): **`{값}`** (볼드 + 백틱)
- **가변값**(사용자 선택·환경별): `{설명}` (중괄호 + 백틱만, 볼드 없음) — 예: `{구독 선택}`, `{할당된 Static IP}`
- 리소스명: `{리소스명}` (백틱만)
- 필드명: 그대로 (볼드 없음)

**실습 설정값은 아래 "실습 설정 표"로 정형화**한다. 개념부의 선택지 *비교*는 비교표, 개념 *서술*은 프로즈로 구분한다.

### 실습 설정 표

콘솔 폼 입력값은 **탭 단위로 묶어 표**로 쓴다(불릿 리스트 아님). `비고`에는 그 설정의 **왜/구조적 의미**를 적어, 클릭 나열이 아니라 구조를 드러낸다. `**{탭명}**` 헤더도 메뉴 경로처럼 **한글만**으로 쓴다(콘솔 표기 그대로, `IAM`·`SKU` 등 영문 토큰은 유지. Ch04~).

```
**{탭명}**

| 필드 | 값 | 비고 (왜/구조) |
|------|-----|----------------|
| Size | `Standard_B2ls_v2` | 2 vCPU·4 GiB, Bsv2 현세대 |
| SKU  | `Standard`        | Basic 은퇴, Secure-by-default |
```

## 콘솔 경로 표기

> 콘솔 경로 형식은 `CLAUDE.md > 플랫폼 상수` 참조.

```
홈 > {서비스 한글} > {하위 메뉴 한글} > **{최종 화면 한글}**
```

- `>` 구분자, 루트는 `홈`(콘솔 breadcrumb와 일치)
- 최종 화면(작업 대상)만 **볼드**
- **메뉴 경로는 한글만.** 콘솔에 뜨는 한글 표기 그대로 쓰고, 별도 `(영문)` 병기를 붙이지 않는다. 단 `IAM`·`SKU`처럼 콘솔이 영문 토큰으로 쓰는 건 그대로 둔다.
- 영문 앵커는 개념부 첫 등장 병기에서 확보한다(경로에서 재앵커링 안 함)
- (Ch04~ 적용. Ch01-03은 구 규약 `Azure Portal > 한글(영문)` 유지)

리소스 네이밍은 **`reference/naming/azure-fund-naming.md`**(시리즈 밖 공유 참조)를 따른다. 작성 전 반드시 읽는다.

### RG 정책
- **Section Lab**: 전용 RG `rg-lab{NN}` — 실습 시작 시 생성, 끝에 삭제(RG 삭제 = 자원 일괄 정리)
- **Gallery**: 공용 RG `rg-gallery` — 챕터 넘어 누적, 삭제 안 함

## 상호 참조 — 번호가 아니라 이름으로

다른 섹션·랩을 본문에서 가리킬 때는 **번호(`04.07`·`lab11`)가 아니라 개념·주제명을 `"따옴표"`로** 쓴다. 구조 변경(섹션 병합·재번호)에 참조가 흔들리지 않게 하기 위함이다. (원칙: `feedback_reference_by_name`. 위반이 쌓여 2차에서 전면 린팅했다 — 다시 새지 않게 작성 중 지킨다.)

- 지양: `04.07에서 격리된 Gallery를`, `lab11과 동일하게`
- 지향: `"Gallery Custom VNet 이전"에서 격리된 Gallery를`, `"Load Balancer 구성"과 동일하게`
- 이름 삽입이 문맥상 **군더더기면 차라리 뺀다**: `VM을 만들고(lab05), 디스크 붙이고(lab06)` → `VM을 만들고, 디스크 붙이고`

### 번호가 사는 곳 (예외 — 그대로 둔다)

번호는 **정의 지점에만** 산다. 아래는 참조가 아니라 정의라 번호 유지:

- **랩 정의 헤딩**: `# [실습] lab13: ...` (그 랩이 정의되는 곳)
- **리소스 이름**: `rg-lab13`·`vm-lab13-web`·`stlab17` (project 토큰 = `lab{NN}`, 네이밍 규칙)
- **draft 파일명·SSOT·syllabus**: `04.07.claude.notion.md`, series-hierarchy·syllabus 표 (번호가 정본 인덱스)
- **README의 자기 섹션 lab 언급**: 그 README가 자기 랩을 소개하는 `실습(lab13)`

> ⚠️ 리소스명은 `st`/`cr`처럼 하이픈 없이 `lab` 뒤에 붙기도 한다(`stlab17`). 번호 관련 일괄 치환 시 **리소스 프리픽스까지 반드시 배제**한다.
