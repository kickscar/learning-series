# 07 네트워크 / 02 포트 게시와 노출 범위

게시한 포트가 어디까지 노출되는지를 다룬다. `-p` 의 형식과 생략할 때의 기본값, 실제 매핑의 확인 방법을 정리하고, 게시한 포트가 호스트의 방화벽 규칙을 거치지 않는 문제와 루프백 바인딩을 이용한 대응, 격리 수준에 따른 노출 범위의 설계 기준을 다룬다.

## What you will learn

- `-p [HOST_IP:][HOST_PORT:]CONTAINER_PORT[/PROTOCOL]` 의 요소와 생략할 때의 기본값(모든 주소 `0.0.0.0` · `[::]`, 임의 포트, `tcp`)
- `-P` 와 `EXPOSE` 의 관계, `docker container port` 와 `PORTS` 열로 확인하는 매핑
- 모든 주소에 게시한 포트와 루프백(`127.0.0.1`)에 게시한 포트의 접속 범위(호스트, 호스트의 외부 주소, 다른 장비)
- 게시한 포트가 ufw · firewalld 규칙을 거치지 않는 문제와 루프백 바인딩을 이용한 대응
- 격리 수준(`none`, 게시 없음, 루프백 게시, 전체 게시)과 노출 범위의 설계 기준

## Examples

- `lab01` → 노출 범위 확인 (모든 주소 게시와 루프백 게시의 접속 범위, 호스트 포트를 생략한 게시와 `-P` 의 임의 포트)
- `lab02` → 방화벽과의 관계 (ufw 활성 상태에서 호스트 서비스와 게시한 컨테이너 포트의 접속 비교, 루프백 게시를 이용한 대응, 방화벽 복원)
